# Wildfire Rescue Queue: web

Vite + React 18 + TypeScript. Three screens on one live SpacetimeDB database:
`/help` (resident phone), `/command` (incident command, desktop) and `/crew` (responder phone).
Everything is simulated. The source of truth is `../claude/frontend-spec.md`, with contract
details from `../claude/frontend-shapes.md`.

## Run it

1. Start the backend from the repo root: `MAILBOX_AGENTS=none scripts/dev.sh reset` (set `MAILBOX_AGENTS=none` in `.env` too, since the script loads `.env` after the prefix).
2. `cp .env.example .env.local` and adjust. Every connection setting lives in `VITE_*` vars, so the same build can point at the local sandbox or a hosted database:
   - `VITE_STDB_URI`: `ws://127.0.0.1:3000` locally, or the hosted URI (for Maincloud, `wss://maincloud.spacetimedb.com`).
   - `VITE_STDB_DB`: the database name.
   - `VITE_MAP_STYLE_URL`: vector map style (CARTO Dark Matter by default; keep its attribution visible).
   - `VITE_INTAKE_URL`: optional Claude intake endpoint. Empty means manual fields only.
3. `npm ci`, then `npm run dev` and open http://localhost:5173.

The dev-only `/_debug` route shows live row counts for every table and view and the ticking sim clock (`?as=help|command|crew` picks the identity).

## Scripts

| Command | What it does |
|---|---|
| `npm run dev` | Dev server on port 5173 |
| `npm run build` | Typecheck, then production build |
| `npm run typecheck` | `tsc --noEmit` over src and tests |
| `npm test` | Unit tests (Vitest, `tests/unit`) |
| `npm run test:e2e` | Playwright against the running local database (`tests/*.spec.ts`) |
| `npm run bindings` | Regenerate `src/module_bindings` from `../spacetimedb` |

Playwright reads `OPERATOR_PASSCODE` from the repo-root `.env` at runtime. First run: `npx playwright install chromium`.

## Layout

- `src/module_bindings/`: generated by `spacetime generate`. Never edit by hand; whoever changes `spacetimedb/src` regenerates and commits them.
- `src/lib/`: the shell. Screens import data only from here: `useTable`, `useView`, `useSingleton`, `useConnection` and `call`/`useCall` (`lib/stdb`), `login` (`lib/auth/operator`), sim time (`lib/time/sim`), grid math and map layers (`lib/geo`), domain constants (`lib/domain`), the guide engine (`lib/guide`) and UI primitives (`lib/ui`).
- `src/routes/{help,command,crew}/`: the screens.
- `tests/unit/`: Vitest. `tests/*.spec.ts`: Playwright.

Each screen keeps its own identity token in localStorage (`stdb_token:<surface>`), saved with the server it belongs to, so switching between the sandbox and a hosted database never reuses a token the other server would reject.
